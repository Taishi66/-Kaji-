# Event log append-only par session — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Journaliser chaque tour au fil de l'eau (append-only) pour restart-safe + audit des approbations + trace prompt→issue — spec `docs/superpowers/specs/2026-08-12-event-log-design.md`.

**Architecture:** Table `session_events` dans `sessions.db` (migration v15→v16). Un seul point d'écriture des `AgentEvent` : `Agent::reply()` (agent.rs:1811, où legacy et state-machine convergent — parité par construction), qui enveloppe le stream dans un `async_stream::try_stream!` appendant `turn_start`, chaque événement, puis `turn_end` en fin normale. Un 2e hook dans `Agent::handle_confirmation` (agent.rs:1553) pour les décisions y/n. `Agent` a déjà `pub session_manager: Arc<SessionManager>` (agent.rs:189) → append direct, pas de trait injecté. Détection de tour interrompu au seed kaji-cli.

**Tech Stack:** sqlx/SQLite (pool existant, WAL), async_stream, serde_json.
