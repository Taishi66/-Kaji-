## Task 1 : Marges intérieures des volets — 1 ligne haut/bas, 1 colonne gauche/droite — constat user 2026-08-19

**Contexte.** Capture user : dans le bloc `chat`, la première ligne (`· 鍛冶 bienvenue…`) touche la bordure haute ; dans le composer `message`, `écris ici…` touche la bordure haute et la bordure basse est immédiatement suivie de la barre d'état ; le lecteur et l'explorateur affichent leur contenu dès la ligne sous la bordure. Objectif : le vide (間) autour du texte dans **tous** les volets bordés, sans casser scroll, overflow, hit-tests souris ni la hauteur minimale.

**Spécification.**

1. **Chat** — `CHAT_VERTICAL_MARGIN: u16 = 1` à côté de `CHAT_HORIZONTAL_MARGIN` ; `chat_content_rect(inner)` rend `y: inner.y + 1`, `height: inner.height.saturating_sub(2)` (en plus de la marge horizontale existante). Tout ce qui dépend de `chat_rect` (wrap, `base_scroll`, `chat_overflow`, `user_turn_rows`, rendu du `Paragraph`) suit automatiquement ; vérifier que **rien** d'autre dans `draw_chat` ou dans les hit-tests souris (`user_turn_rows`, molette, clic sur un tour) n'utilise `inner` ou `area` là où il faudrait `chat_rect` — sinon corriger.
2. **Composer** — colonne principale `[Min(3), Length(3)]` → `[Min(3), Length(5)]` (idem dans le layout de test ~ligne 1903 si c'est le même calcul) ; dans `draw_input`, la zone de contenu devient `y: inner.y + 1`, `height: 1` (une ligne d'entrée, une ligne vide au-dessus et en dessous), marge gauche existante conservée. Le curseur (`frame.set_cursor_position` ou équivalent) suit la nouvelle zone. Palette `/`, mentions `@` et tout overlay ancré sur `column[1]` continuent de s'ancrer correctement (vérifier `draw_palette`/`draw_mentions` : ancrage au-dessus du composer, pas de chevauchement du composer agrandi).
3. **Lecteur** (`draw_viewer`) — `visible = area.height.saturating_sub(4)` (bordures + marges) ; contenu rendu à partir de `inner.y + 1` avec une colonne de marge à gauche si le texte touche la bordure aujourd'hui ; `viewer_area` (molette) et le calcul « première ligne visible » (`e` ouvre à la 1re ligne visible) restent cohérents avec la zone de contenu ; le pied (`title_bottom`) inchangé.
4. **Explorateur** (`draw_explorer`) — `rows = area.height.saturating_sub(4)` ; entrées rendues à partir de `inner.y + 1` avec une colonne de marge à gauche ; le curseur/`position` et le défilement de la liste suivent `rows`.
5. **Panneau SPEC** (`draw_spec`) — même marge 1 ligne haut/bas et 1 colonne gauche si son contenu touche la bordure.
6. **Hauteurs minimales** — un terminal de 12 lignes ne doit pas paniquer ni rendre du contenu par-dessus une bordure : toutes les soustractions en `saturating_sub`, `Constraint::Min(3)` du chat conservé (à 3 lignes le chat a 0 ligne utile mais ne panique pas).
7. **Ne pas toucher** : header (ligne 0), barre d'état (dernière ligne), largeur des colonnes (Task 20), `CHAT_MAX_WIDTH`.

**Tests (TDD).**

- `ui.rs` : (a) `chat_content_rect` d'un `inner` `y=1,height=10` → `y=2,height=8` ; (b) rendu `rendered(&app, 100, 20)` avec un chat non vide : la ligne juste sous la bordure haute du bloc chat est **vide** (hors bordure) et le premier texte est 2 lignes sous la bordure ; (c) composer : dans un rendu, la ligne du placeholder `écris ici…` est séparée de la bordure haute et de la bordure basse du bloc `message` par une ligne vide chacune ; (d) lecteur ouvert sur un fichier de 100 lignes dans un volet de hauteur 20 : 16 lignes de contenu visibles, la première sous une ligne vide ; (e) explorateur : même invariant (`rows = height - 4`) ; (f) hauteur 12 avec chat + composer : aucun panic, la barre reste sur la dernière ligne ; (g) `chat_overflow`/scroll : ouvrir un chat de 50 lignes en hauteur 20 → `End` colle la dernière ligne au-dessus de la marge basse (pas sous la bordure) — adapter les tests existants qui comptent des lignes depuis la bordure.
- Suite complète verte, clippy vert, rustfmt par fichier.

**Commit.** `feat(tui): marges intérieures — une ligne de vide haut/bas et une colonne gauche/droite dans le chat, le composer, le lecteur, l'explorateur et le panneau SPEC`. Fichiers : `crates/kaji-cli/src/tui/ui.rs` (+ `viewer.rs`/`explorer.rs` seulement si un calcul de lignes visibles y vit).
